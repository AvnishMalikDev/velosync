    Jira (required)

    Written to Product/.env. Blank secret fields keep the value already on disk. Saved tokens stay masked in the form—edit the field only when you intend to replace a value. How many sprints to export is set per project under Projects.

    Optional Jira custom fields (global fallback)

    Defaults are discovered from Jira when empty. Per-project overrides (including work classification) live in each row under Projects → details.

    Optional connectors

    Toggles are stored in data/connectors.json. The export pipeline only pulls data for enabled connectors. Jira is always on.

    Credentials

    Tokens stay masked; leave a field blank to keep the value already on disk.

    HTTPS / SSL

    Upload your certificate chain and private key (PEM). Files are stored under Product/ssl/ as server.key and server.crt, and USE_HTTPS=1 plus paths are written to Product/.env. You can also set USE_HTTPS, PUBLIC_BASE_URL, PORT, and paths under Platform without SSH. After any change, restart the Node process (e.g. pm2 restart all on the host) so TLS and listeners reload.

    Platform & SSO

    Auth, optional Microsoft Entra (Azure AD), session, URLs, port, and HTTPS flags. Default is local username/password. Microsoft SSO uses AUTH_MODE=azure (shown automatically once Entra Client ID, Tenant, and Secret are set). Use ALLOW_LOCAL_LOGIN=1 to keep username/password alongside Microsoft. All values are saved to Product/.env (canonical). After changing auth, session, URL, port, or TLS, save and restart the Node process on the host (see the green notice). Secret fields stay masked; leave blank to keep the saved value.

    Microsoft Entra (Azure AD) is azure. When Client ID, Tenant, and Secret are all set, this field switches to azure so it matches your configuration. Set ALLOW_LOCAL_LOGIN=1 to keep both Microsoft and username/password on the login page.

    Process manager (PM2)

    If you run the web app under PM2, set the name to match pm2 start … --name …. After saving platform settings, restart the process on the host (see the green notice after save)—the in-browser restart control is disabled in this build.

    By default, AUTH_MODE is local (username/password only). Use AUTH_MODE=azure for Microsoft sign-in, and optionally ALLOW_LOCAL_LOGIN=1 to keep both buttons on the login page. Bootstrap admin / admin is created when no local users exist and local login is allowed.

    Microsoft admin names

    One display name per line. Fuzzy-matched to Microsoft sign-in. (Hidden when using local-only auth.)

    Local accounts

    Used for username/password sign-in (AUTH_MODE=local, ALLOW_LOCAL_LOGIN=1, or Azure not configured yet). Accounts live in rbac.json; if the file is missing and local sign-in is allowed, the server creates it on startup with a bootstrap admin user (change the password after first login).

    Configure weights

    Health Matrix, devData, and qaData are loaded from the server on each dashboard load. Save scoring config writes the normalized values to jira-md-export/Template/dashboard-scoring.template.json immediately. An optional jira-md-export/dashboard-scoring.json can still supply local overrides if you add keys there by hand; Admin save clears that file so the template stays authoritative. Legacy main/detail split keys are merged when read.

    Data Sync Job (jira-md-export)

    You can install this Product anywhere on disk; paths below are relative to the Product folder (the one that contains server.js). The job runs jira-md-export/index.js on a PM2 cron schedule and reads Product/.env, jira-md-export/projects.json, and connector settings each run. After you save platform secrets, projects, or connectors, the server asks PM2 to restart this process (when enabled) so the next run sees fresh files.

    —

    Example: 0 * * * * hourly; 0 2 * * * daily at 02:00. See crontab.guru.

    Requires pm2 on PATH (npm i -g pm2). PM2 is started with cwd = Product root and a relative script path. Saving writes data/data-sync-job.json and ecosystem.data-sync.config.cjs (portable __dirname-based paths).
